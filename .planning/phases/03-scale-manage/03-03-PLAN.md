## Phase Goal

**As a** wallet holder, **I want to** view all my gift cards in a filterable dashboard with multi-select bulk actions and detailed card views, **so that** I can manage hundreds of issued cards efficiently.

<objective>
Deliver the dashboard management console: server-side filtered queries (status, search, date range), multi-select with bulk actions (Send All Emails, Download CSV), card detail dialog with full information, and CSV export of filtered/selected cards. This plan implements the filtered query backend, the filter bar UI, multi-select checkboxes, bulk action buttons, and the detail dialog. The edit and delete dialogs were implemented in Plan 02; this plan adds the "View Full Details" dialog and wires the filter/multi-select/bulk-action UI.

Purpose: Makes the card list manageable at scale with filtering, batch operations, and detailed inspection.
Output: get_cards_by_wallet_filtered CRUD, filter bar UI, multi-select q-table, bulk action buttons, card detail dialog, CSV export of filtered/selected cards.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API (filtered query) | Filter params (status, search, date range) cross here — must be parameterized to prevent SQL injection |
| Browser → API (bulk email) | Batch email trigger crosses here — must verify ownership per card |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Tampering | GET /cards filter params | high | mitigate | All filter values use parameterized SQL (:status, :search, timestamp_placeholder); no string interpolation of user input into query (RESEARCH.md Pattern 4) |
| T-03-15 | Information Disclosure | GET /cards cross-wallet | high | mitigate | WHERE wallet = :wallet clause always present; wallet_id derived from API key not request body (D-10) |
| T-03-16 | Elevation of Privilege | Bulk email send all | medium | mitigate | sendBulkEmails calls existing POST /cards/{id}/deliver per card which has ownership check (views_api.py line 315) |
| T-03-17 | Denial of Service | Search query performance | low | mitigate | m004 index on (wallet, status, created_at) improves filter query performance; debounce=300 on search input prevents excessive calls |
</threat_model>
