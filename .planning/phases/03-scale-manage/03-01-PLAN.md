<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External system → API (invoice key) | Untrusted read requests cross here — invoice key holder can list/view cards but must not see redemption_url by default |
| External system → API (admin key) | Write requests (bulk create) cross here — admin key holder can create cards debiting the wallet |
| Browser → API (admin key) | Issuer UI sends admin key for bulk creation — wallet debited per card |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | POST /cards/bulk | high | mitigate | require_admin_key decorator validates admin key; wallet derived from key not request body (D-10) |
| T-03-02 | Information Disclosure | GET /cards/{id} response | high | mitigate | CardDetailResponse defaults redemption_url to None; only populated when ?include_link=true explicitly passed (D-11) |
| T-03-03 | Elevation of Privilege | GET /cards/{id} | high | mitigate | Ownership check: card.wallet != wallet.wallet.id → 403; invoice key derives wallet scope (D-10) |
| T-03-04 | Denial of Service | POST /cards/bulk | medium | mitigate | BulkCreateRequest.count Field le=500 prevents excessive card creation; @validator enforces max 500 (D-08) |
| T-03-05 | Tampering | Wallet balance during bulk | medium | mitigate | Each create_gift_card call debits issuer wallet; insufficient balance causes update_wallet_balance failure which stops the loop |
| T-03-06 | Repudiation | Bulk creation logging | low | accept | logger.error on failures provides audit trail; no additional repudiation control needed for v1 |
</threat_model>
