## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none (Quasar Framework via LNBits core) | RESEARCH.md — standard stack |
| Preset | not applicable — LNBits provides Quasar 2 globally | codebase: `/lnbits/static/vendor/quasar.css` |
| Component library | Quasar 2 (`q-card`, `q-btn`, `q-input`, `q-dialog`, `q-table`, `q-form`) | codebase: `events/static/js/index.vue` |
| Icon library | Material Icons (self-hosted in LNBits core) | codebase: `lnbits/templates/base.html` — `material-icons-v50.woff2` |

| Vue version | Vue 3 (Composition API optional, Options API in reference) | codebase: `events/static/js/index.vue` |

**shadcn gate:** Not applicable. This is a Quasar/Vue extension, not a React/Next.js/Vite project. No `components.json` exists or is needed.

**Theme tokens:** LNBits ships 9 SCSS themes. Extensions receive `$primary`, `$secondary`, `$dark`, and `$accent` CSS custom properties from the active theme at runtime. Extensions MUST NOT hardcode hex colors from a specific theme. Use Quasar color prop names (`color="primary"`, `color="accent"`) and CSS variable references only.

## Spacing Scale

Declared values (must be multiples of 4). Quasar utility class equivalents shown for executor reference.

| Token | Value | Quasar class | Usage |
|-------|-------|--------------|-------|
| xs | 4px | `q-pa-xs` / `q-ma-xs` | Icon gaps, badge padding, inline chip spacing |
| sm | 8px | `q-pa-sm` / `q-gutter-sm` | Compact element spacing, button row gaps |
| md | 16px | `q-pa-md` / `q-gutter-md` | Default element spacing, form field gaps |
| lg | 24px | `q-pa-lg` / `q-col-gutter-md` | Card padding, section padding |
| xl | 32px | `q-pa-xl` | Dialog padding (`q-pa-lg q-pt-xl` — events pattern) |
| 2xl | 48px | — | Major section breaks (page-level padding) |
| 3xl | 64px | — | Reserved; not used in Phase 1 |

Exceptions:
- Touch targets (mobile): minimum 44px height for all interactive elements on the public redemption page (CONTEXT.md: "mobile-first"). Quasar `size="lg"` on buttons satisfies this.
- QR code display: fixed 240px × 240px on mobile, 300px × 300px on desktop. Not on the 8-point scale by design.

## Typography

LNBits extensions inherit Quasar's typographic scale via `bundle.min.css`. Do not override base font. Use Quasar text utility classes.

| Role | Size | Weight | Line Height | Quasar class | Usage |
|------|------|--------|-------------|--------------|-------|
| Body | 14px | 400 (regular) | 1.5 | `text-body2` | Form labels, list rows, descriptive text |
| Label | 12px | 400 (regular) | 1.4 | `text-caption` | Field hints, secondary metadata (e.g. expiry date, token id) |
| Heading | 20px | 600 (semibold) | 1.3 | `text-h6` | Card section titles, dialog titles |
| Display | 28px | 600 (semibold) | 1.2 | `text-h5` | Sats amount on redemption page (primary focal point) |

Maximum 4 sizes, 2 weights used. Do not introduce additional sizes.

## Color

Extensions receive theme color variables at runtime from the active LNBits theme. Reference by Quasar color prop name only.

| Role | Quasar token | Usage |
|------|--------------|-------|
| Dominant (60%) | `body--light` / `body--dark` background | Page background, main surface — do not set explicitly |
| Secondary (30%) | `q-card` default surface | Cards (`q-card`), dialog backgrounds — Quasar handles automatically |
| Accent (10%) | `color="primary"` | Primary CTA buttons only (see reserved list below) |
| Destructive / error state | `color="negative"` | Destructive confirmation and invalid/error icon states — no decorative use |
| Success state | `color="positive"` | Active status badge only |
| Completed state | `color="grey-6"` | Redeemed status badge only |
| Warning state | `color="warning"` | Expired status badge only |
| Neutral action | `color="grey-7"` (dark) / `color="grey-5"` (light) | Secondary icon buttons (events pattern: link/copy buttons) |

**Accent (`primary`) reserved for:**
1. "Create Gift Card" primary CTA button (issuer page)
2. "Redeem" / LNURL-withdraw trigger button (public redemption page)

**Accent (`primary`) NOT used for:** status badges, secondary actions, table row expanders, copy-link buttons, info icons, or any decorative element.

**Dark mode:** All color references use Quasar's `$q.dark.isActive` responsive pattern (see events reference: `color="$q.dark.isActive ? 'grey-7' : 'grey-5'"`). No hardcoded hex values anywhere in Vue components.

## Screen Contracts

### Screen 1: Issuer Extension Page (`/giftcards/`)

**Layout:** Two-column responsive (matches events pattern: `col-12 col-md-8 col-lg-7` main + `col-12 col-md-4 col-lg-5` info panel). On mobile: single column stack.

**Component structure:**
```
q-layout (from LNBits base.html — inherited, do not re-declare)
└── q-page-container
    └── q-page (class: q-px-md q-py-lg)
        └── div.row.q-col-gutter-md
            ├── div.col-12.col-md-8.col-lg-7.q-gutter-y-md   ← main column
            │   ├── q-card (CTA card)
            │   │   └── q-card-section
            │   │       └── q-btn [primary] "Create Gift Card"
            │   └── q-card (card list)
            │       └── q-card-section
            │           ├── row: h5 "Gift Cards" + q-btn[flat,grey] "Export CSV"
            │           └── q-table (gift cards list)
            └── div.col-12.col-md-4.col-lg-5.q-gutter-y-md   ← info column
                └── q-card (info/help)
                    └── q-expansion-item "About Gift Cards"
```

**Gift card list table columns (Phase 1 — no status filter, no bulk actions):**

| Column | Data | Notes |
|--------|------|-------|
| Amount | `{amount} sats` | Right-aligned numeric |
| Recipient | `recipient_name` | Truncate at 20 chars |
| Status | Badge: `active` / `redeemed` / `expired` | Color-coded (see Status Badge contract below) |
| Expires | `expires_at` formatted as `YYYY-MM-DD` or "Never" | — |
| Actions | Copy link icon button + expand row icon button | `icon="link"` + `icon="expand_more"` |

**Expanded row (inline detail):** Shows sender name, message, creation date, and redemption link as a copyable text field. No sub-table.

**Status Badge contract:**

| Status | Quasar color | Label |
|--------|--------------|-------|
| `active` | `positive` | Active |
| `redeemed` | `grey-6` | Redeemed |
| `expired` | `warning` | Expired |

### Screen 2: Create Gift Card Dialog

**Trigger:** "Create Gift Card" button on issuer page.

**Component:** `q-dialog` with `position="top"`, `q-card.q-pa-lg.q-pt-xl.lnbits__dialog-card` (standard LNBits dialog pattern from events reference).

**Form fields (in order):**

| Field | Quasar component | Type | Required | Notes |
|-------|-----------------|------|----------|-------|
| Wallet | `q-select` filled dense | wallet picker | Yes | Pre-populated with current LNBits wallet; `v-model="formDialog.data.wallet"` |
| Amount (sats) | `q-input` filled dense | `type="number"` | Yes | Min: 1. Label: "Amount (sats)". Hint: "Sats will be locked from your wallet at creation." |
| Recipient Name | `q-input` filled dense | `type="text"` | No | Label: "Recipient Name". Hint: "Optional — shown on the redemption page." |
| Sender Name | `q-input` filled dense | `type="text"` | No | Label: "Your Name". Hint: "Optional — shown as sender on the redemption page." |
| Message | `q-input` filled dense | `type="textarea"` | No | Label: "Personal Message". Hint: "Optional — shown to recipient." |
| Expiration Date | `q-input` filled dense | `type="date"` | No | Label: "Expires On". No date = card never expires. |

**Submit button:** `q-btn unelevated color="primary" type="submit"` — label: "Create Gift Card"

**Cancel button:** `q-btn flat color="grey"` — label: "Discard Gift Card" — `v-close-popup`

**Post-creation result state (inline in dialog, replaces form):**
- Show success message: "Gift Card Created"
- Display redemption link as a copyable `q-input readonly` field with copy icon button
- Warn (once, prominently): "Save this link — it cannot be recovered." Use `q-banner` with `color="warning"` icon `warning`
- Button: "Create Another" (resets form) + "Close Dialog" (closes dialog)

### Screen 3: Public Redemption Page (`/giftcards/redeem/{raw_token}`)

**Route type:** Public, no LNBits account required. Served via `index_public` pattern (see events `views.py` reference). LNBits header and drawer are NOT shown on public pages.

**Layout:** Single centered column — `div.row.justify-center` → `div.col-12.col-md-7.col-lg-6.q-gutter-y-md` (matches events `ticket.vue` pattern).

**Mobile-first requirement (from CONTEXT.md):** All interactive elements minimum 44px touch target. QR code minimum 240px. Page must be fully functional at 375px viewport width.

**States and their UI:**

#### State A: Active — card is redeemable

```
q-card.q-pa-lg
└── q-card-section.q-pa-none
    └── center
        ├── h5.text-h5 (display)   "{amount} sats"           ← 28px semibold (Display typography)
        ├── p.text-body2           "From {sender_name}"       ← show only if sender_name set
        ├── p.text-body2.q-mt-md   "{message}"                ← show only if message set
        ├── p.text-caption.q-mt-sm "For {recipient_name}"     ← show only if recipient_name set
        ├── [divider]
        ├── p.text-body2.q-mt-md   "Scan with your Lightning wallet to redeem:"
        ├── lnbits-qrcode          :value="lnurlWithdrawUrl"  ← 240px mobile, 300px desktop
        │                          :options="{width: 300}"
        ├── q-btn[unelevated,primary,size="lg"] "Redeem via Lightning Wallet"
        │   (href = lnurl:// deep link or lightning: URI, opens wallet on mobile)
        ├── [divider]
        └── p.text-caption         "Expires: {expires_at formatted}" or "No expiration"
```

**QR code value:** The HTTPS LNURL-withdraw params URL — `https://{base_url}/giftcards/api/v1/lnurl/{token_hash}`. Modern Lightning wallets GET this URL and receive `{"tag":"withdrawRequest",...}`. See RESEARCH.md Pattern 3 and Pattern 6.

**"Redeem" button href:** `lightning:{lnurl_bech32_encoded}` (opens wallet app on mobile). If bech32 encoding is not implemented in Phase 1, omit the button and rely on QR only — do not ship a broken deep link.

#### State B: Already redeemed

```
q-card.q-pa-lg
└── q-card-section
    └── center
        ├── q-icon(name="check_circle", color="positive", size="64px")
        ├── h5.text-h6.q-mt-md    "This gift card has been redeemed"
        └── p.text-body2.text-grey "This card was already redeemed. If you believe this is an error, contact the sender."
```

#### State C: Expired

```
q-card.q-pa-lg
└── q-card-section
    └── center
        ├── q-icon(name="schedule", color="warning", size="64px")
        ├── h5.text-h6.q-mt-md    "This gift card has expired"
        └── p.text-body2.text-grey "The card expired on {expired_at date}. The sats have been returned to the issuer."
```

#### State D: Not found / invalid token

```
q-card.q-pa-lg
└── q-card-section
    └── center
        ├── q-icon(name="error_outline", color="negative", size="64px")
        ├── h5.text-h6.q-mt-md    "Gift card not found"
        └── p.text-body2.text-grey "This link may be invalid or the card may have been removed. Check the link and try again."
```

#### State E: Loading (while API call in flight)

```
q-card.q-pa-lg
└── q-card-section
    └── center
        └── q-spinner(color="primary", size="48px")
```

## Interaction Contracts

### Create form — field validation

| Field | Rule | Error message |
|-------|------|---------------|
| Amount | Required, integer ≥ 1 | "Amount is required and must be at least 1 sat." |
| Amount | Must not exceed wallet balance | "Amount exceeds your wallet balance." |
| Expiration Date | If set, must be in the future | "Expiration date must be in the future." |
| All others | Optional — no validation error | — |

Validation fires on form submit only (not on blur). Use `q-form @submit` with `lazy-rules` on `q-input`.

### Copy-link button behavior

On click: copy redemption URL to clipboard, show `q-notify` with `type="positive"` and message "Link copied to clipboard." Duration: 2000ms. No persistent toast.

### Redemption page — polling

The redemption page Vue component calls `GET /giftcards/api/v1/cards/public/{token_hash}` on mount to retrieve card state. No auto-polling after initial load in Phase 1. Recipient refreshes manually if needed.

**API response shape for public redemption page** (no sensitive fields — matches CONTEXT.md privacy requirement):

```json
{
  "status": "active" | "redeemed" | "expired",
  "amount": 1000,
  "sender_name": "Alice",
  "recipient_name": "Bob",
  "message": "Happy birthday!",
  "expires_at": "2026-12-31T00:00:00Z" | null,
  "expired_at": "2026-07-15T00:00:00Z" | null,
  "lnurl_withdraw_url": "https://.../giftcards/api/v1/lnurl/{token_hash}"
}
```

Fields NOT exposed publicly: `wallet`, `card_wallet`, `token_hash`, `redeemed_at` (exact timestamp — privacy).

## Accessibility Notes

- All `q-btn` elements that are icon-only must include `aria-label` (e.g., `aria-label="Copy redemption link"`).
- QR code image must include `alt="LNURL QR code for gift card redemption"`.
- Error and status states use both color AND icon (not color alone) to satisfy WCAG 1.4.1 (Use of Color).
- Public redemption page: no LNBits header/drawer chrome — page is self-contained. Tab order: amount → message → QR → redeem button.
