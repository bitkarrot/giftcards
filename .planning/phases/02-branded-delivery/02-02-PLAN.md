## Phase Goal

**As an** LNBits wallet holder, **I want to** interactively design my gift card by dragging the QR code and text on a live preview with styling controls, **so that** I can create a visually appealing branded card without needing design tools.

## Acceptance Criteria

- [ ] The create dialog has a "Card Design" section below the existing form fields with a q-separator and heading.
- [ ] A q-select offers three template options: "Portrait (425x650)", "Landscape (1050x600)", "Custom Upload".
- [ ] Selecting "Custom Upload" reveals an "Upload Custom Template" button that triggers a hidden file input; on file selected, it uploads via POST /api/v1/assets?public_asset=true and stores the asset_id.
- [ ] A live preview container (div.card-preview) shows the template background with a draggable QR element and a draggable text element positioned via pointer events.
- [ ] The QR element has a resize handle (div.resize-handle) at the bottom-right corner; dragging it resizes the QR with a minimum of 150px enforced.
- [ ] Text styling controls include: q-select for font (DejaVu Sans, DejaVu Serif, DejaVu Sans Mono), q-slider for font size (12-72, default 24), q-input type="color" for font color (default #000000), q-btn-toggle for alignment (left/center/right).
- [ ] The preview text shows live values: "{amount} sats", "For: {recipient_name}", "{message}".
- [ ] No server round-trips occur during drag or resize — all updates are client-side reactive state.
- [ ] On submit, positions are converted to normalized fractions (0.0-1.0) and sent as a design config object with the card creation request.
- [ ] If the issuer skips the design section (no template selected), defaults apply: portrait template, QR at (0.1, 0.7) frac, size 200px, DejaVu Sans 24px black left-aligned text at (0.1, 0.1) frac.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Issuer browser → LNBits asset API | Custom template upload crosses here; uploaded images are validated by create_user_asset (MIME type, size limit) |
| Client-side preview → server render | Design config (normalized fractions, font settings) is sent from the browser to the create endpoint; server validates and clamps QR size |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-02-01 | Tampering | Client-side QR size | medium | mitigate | Client enforces minQrSize=150 in onResize; server-side renderer also clamps with max(150, qr_size) in _render_card_image_sync. Defense in depth. |
| T-02-02-02 | Tampering | Client-side coordinates | low | accept | Normalized fractions (0.0-1.0) are inherently bounded; out-of-range values result in off-canvas rendering (cosmetic issue, not security). |
| T-02-02-03 | Tampering | Template upload | medium | mitigate | Uses LNBits core asset system (create_user_asset) which validates MIME type against settings.lnbits_assets_allowed_mime_types and enforces size limit (lnbits_max_asset_size_mb). |
| T-02-02-04 | Information Disclosure | Template asset_id | low | accept | asset_id is stored on the card record and used only for rendering; it is not exposed in public endpoints (only in issuer-authenticated list). |
| T-02-02-SC | Tampering | Python package installs | high | mitigate | This plan installs no new runtime Python packages. |

</threat_model>
