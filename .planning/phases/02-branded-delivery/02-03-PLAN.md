## Phase Goal

**As an** LNBits wallet holder, **I want to** deliver a gift card to a recipient via email with a secure magic link verification flow, **so that** the recipient can verify their email, see their pending cards, and redeem without the raw token ever being sent in an email.

## Acceptance Criteria

- [ ] Issuer can trigger email delivery from the card list via an email delivery dialog with recipient email, mode (custom/fancy), subject, and body fields.
- [ ] The notification email contains the sender's name, a link to /giftcards/claim, and does NOT contain the raw_token or branded card image.
- [ ] The recipient visits /giftcards/claim, enters their email, and always sees "Check Your Email" confirmation (no email enumeration).
- [ ] If pending cards exist, a magic link email is sent with a 30-minute TTL; the magic link URL is /giftcards/claim/{magic_token}.
- [ ] Magic link tokens are generated with secrets.token_urlsafe(32); only SHA-256 hashes are stored in the database.
- [ ] Rate limiting: max 3 magic link requests per email per hour, enforced DB-backed before generating a link; 429 response when exceeded.
- [ ] The magic link landing page (GET /giftcards/api/v1/claim/{magic_token}) returns a list of pending cards with raw_tokens for redirect to /giftcards/redeem/{raw_token}.
- [ ] Magic links are invalidated (deleted) when any card for that email is redeemed.
- [ ] Email delivery status (not_sent/sent/failed) is updated on the card record and visible in the card list.
- [ ] SMTP send uses LNBits global settings (settings.lnbits_email_notifications_*) and is offloaded via asyncio.to_thread or create_task.
- [ ] If SMTP is not configured, the deliver endpoint returns an error and the card's email_status is set to "failed".
- [ ] Jinja2 HTML email templates exist in static/email_templates/ with autoescape enabled.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Public internet → claim endpoint | Anyone can POST /claim with any email; the endpoint must not reveal whether cards exist for that email |
| Public internet → magic link verification | Anyone with a valid magic_token can see all pending cards for that email; the token is a bearer token proving email ownership |
| Issuer browser → deliver endpoint | Authenticated via require_admin_key; only the card's issuer can trigger email delivery |
| Extension → SMTP server | Email send crosses to external SMTP; credentials come from LNBits global settings |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-03-01 | Spoofing | Magic link token guessing | high | mitigate | Token generated with secrets.token_urlsafe(32) = 256 bits of entropy. Only SHA-256 hash stored. Infeasible to brute-force. |
| T-02-03-02 | Information Disclosure | Email enumeration via claim endpoint | high | mitigate | POST /claim always returns the same response message regardless of whether cards exist for the email. No timing difference (email send is fire-and-forget or always attempted). D-14. |
| T-02-03-03 | Denial of Service | Rate limit bypass on claim endpoint | high | mitigate | DB-backed rate limit: count_recent_magic_links checks magic_links table for rows with email AND created_at > now-3600. If >= 3, return 429. Checked BEFORE generating a link. D-13. Survives restarts, works across workers. |
| T-02-03-04 | Replay | Magic link replay after redemption | high | mitigate | After mark_redeemed, invalidate_magic_links_for_email deletes all magic_links rows for the card's email. The recipient cannot re-access the card page via the same magic link. D-16. |
| T-02-03-05 | Tampering | Magic link TTL bypass | high | mitigate | get_magic_link_by_hash checks expires_at > now (timezone-aware). Magic links past 30 minutes are not returned. used_at is set on first verification, preventing reuse. |
| T-02-03-06 | Information Disclosure | Raw token in magic link response | medium | mitigate | The magic link verification endpoint returns raw_token ONLY after successful email verification (magic link clicked). The raw_token is never sent in the initial email. D-12. This is the only endpoint outside card creation that exposes raw_token, and it is gated behind email ownership proof. |
| T-02-03-07 | XSS | Sender message in email HTML | high | mitigate | Jinja2 autoescape=select_autoescape(["html", "xml"]) escapes all variables in HTML templates. For custom text mode, body is rendered through Jinja2 autoescape. Matches events extension pattern (services.py:164). |
| T-02-03-08 | Information Disclosure | SMTP credentials | high | mitigate | SMTP credentials come from LNBits global settings (settings.lnbits_email_notifications_*). The extension does not log or expose credentials. SMTP send is wrapped in try/except, errors are logged as warnings without credential details. |
| T-02-03-09 | Tampering | Deliver endpoint wallet scoping | high | mitigate | POST /cards/{card_id}/deliver verifies card.wallet == wallet.wallet.id from require_admin_key before sending. An issuer cannot trigger delivery for another wallet's card. |
| T-02-03-10 | Denial of Service | SMTP blocking event loop | medium | mitigate | _send_smtp_email is synchronous and called via asyncio.to_thread() — does not block the async event loop. RESEARCH.md Risk 2, Pitfall 6. |
| T-02-03-SC | Tampering | Python package installs | high | mitigate | This plan installs no new runtime Python packages; Jinja2, smtplib, email.mime are all already available. |
