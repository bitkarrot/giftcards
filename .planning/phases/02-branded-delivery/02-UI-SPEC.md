## Spacing Scale

Inherited from Phase 1 UI-SPEC. No changes. Quasar utility class equivalents shown for executor reference.

| Token | Value | Quasar class | Usage |
|-------|-------|--------------|-------|
| xs | 4px | `q-pa-xs` / `q-ma-xs` | Icon gaps, badge padding, inline chip spacing |
| sm | 8px | `q-pa-sm` / `q-gutter-sm` | Compact element spacing, button row gaps, drag-handle size |
| md | 16px | `q-pa-md` / `q-gutter-md` | Default element spacing, form field gaps, preview padding |
| lg | 24px | `q-pa-lg` / `q-col-gutter-md` | Card padding, section padding, dialog padding |
| xl | 32px | `q-pa-xl` | Dialog padding (`q-pa-lg q-pt-xl` — events pattern) |
| 2xl | 48px | — | Major section breaks |
| 3xl | 64px | — | Reserved; not used in Phase 2 |

Exceptions (Phase 2 additions):
- **Card designer preview:** Fixed preview dimensions matching template aspect ratio, scaled to fit dialog. Portrait preview: 212×325px (half of 425×650). Landscape preview: 262×150px (quarter-scale of 1050×600). Not on the 8-point scale by design — they are image-dimension-derived.
- **QR resize handle:** 12px × 12px square at the bottom-right corner of the draggable QR element. Below the 16px md token, but necessary for precise resize interaction. Has a 24px (lg) invisible touch padding via `padding` to meet the 44px touch target minimum.
- **Touch targets (claim page, mobile):** minimum 44px height for all interactive elements. Quasar `size="lg"` on buttons satisfies this.

## Typography

Inherited from Phase 1 UI-SPEC. No changes to the UI type scale.

| Role | Size | Weight | Line Height | Quasar class | Usage |
|------|------|--------|-------------|--------------|-------|
| Body | 14px | 400 (regular) | 1.5 | `text-body2` | Form labels, list rows, descriptive text, email body preview |

- DejaVu Sans (default sans-serif)
- DejaVu Serif (elegant serif)
- DejaVu Sans Mono (monospace — third option)

Font size for rendered text: issuer-controlled via `q-slider` (range 12–72px, default 24px). Font color: issuer-controlled via `q-input type="color"` (native color picker, default `#000000`). Text alignment: issuer-controlled via `q-btn-toggle` (left / center / right, default left).

### Screen 1: Card Designer (extends Create Gift Card Dialog)

**Trigger:** "Create Gift Card" button on issuer page — opens existing `q-dialog` (Phase 1), now extended with a design section.

**Integration:** The card designer is a new section inserted into the existing create dialog (`index.vue:169-302`), below the existing form fields (wallet, amount, recipient, sender, message, expiry) and above the submit button row. The dialog remains a single `q-dialog` with `position="top"` and `q-card.q-pa-lg.q-pt-xl.lnbits__dialog-card`.

**Component structure (additions to existing dialog):**
```
q-dialog (existing — position="top")
└── q-card.q-pa-lg.q-pt-xl.lnbits__dialog-card (existing)
    └── q-form (existing)
        └── div.q-gutter-md (existing — form fields above)
            ├── [existing fields: wallet, amount, recipient, sender, message, expiry]
            │
            ├── q-separator.q-my-md                          ← NEW: visual break before design section
            ├── h6.text-subtitle1.q-my-none "Card Design"    ← NEW: section heading
            │
            ├── div.row.q-col-gutter-md                       ← NEW: template selection row
            │   ├── div.col-12.col-md-6
            │   │   └── q-select "Template" (portrait / landscape / custom)
            │   └── div.col-12.col-md-6
            │       └── q-btn "Upload Custom Template" + hidden <input type="file">
            │
            ├── div.row.q-col-gutter-md                       ← NEW: preview + controls row
            │   ├── div.col-12.col-md-7
            │   │   └── div.card-preview (positioned container — drag surface)
            │   │       ├── img.template-bg (template background)
            │   │       ├── div.draggable-qr (pointer events — drag + resize)
            │   │       │   ├── img (QR placeholder)
            │   │       │   └── div.resize-handle (bottom-right corner)
            │   │       └── div.draggable-text (pointer events — drag)
            │   │           └── div (styled preview text: amount / recipient / message)
            │   └── div.col-12.col-md-5
            │       └── div.q-gutter-sm (styling controls)
            │           ├── q-select "Font" (DejaVu Sans / Serif / Mono)
            │           ├── q-slider "Font Size" (min 12, max 72, default 24)
            │           ├── q-input type="color" "Font Color" (default #000000)
            │           └── q-btn-toggle "Alignment" (left / center / right)
            │
            └── div.row.q-mt-lg (existing — submit/cancel buttons)
```

**Template selection (D-01, D-04):**
- `q-select` with three options: "Portrait (425×650)", "Landscape (1050×600)", "Custom Upload".
- Selecting "Custom Upload" reveals the upload button (or auto-triggers file picker).
- Bundled templates show a thumbnail preview next to the select (small `img` 48×72px for portrait, 72×41px for landscape).
- Custom upload: hidden `<input type="file" accept="image/png,image/jpeg">` triggered by `q-btn` click — matches events extension pattern (`events/static/js/index.vue:972-978`). On file selected → `uploadAssetFile()` → `POST /api/v1/assets?public_asset=true` → store `asset_id`. Show upload progress with `q-spinner`. On success, load asset as template background.

**Drag preview (D-05, D-06):**
- Preview container: `div.card-preview` with `position: relative`, `overflow: hidden`, fixed dimensions matching the selected template aspect ratio (scaled to fit dialog — portrait 212×325px, landscape 262×150px).
- Template background: `img.template-bg` with `position: absolute; top: 0; left: 0; width: 100%; height: 100%`.
- Draggable QR: `div.draggable-qr` with `position: absolute`, `left`/`top`/`width`/`height` bound to reactive state. Contains a placeholder QR `img` (any QR image, or generated client-side). Has a `div.resize-handle` at the bottom-right corner (12×12px, `cursor: nwse-resize`).
- Draggable text: `div.draggable-text` with `position: absolute`, `left`/`top` bound to reactive state. Contains a `div` with inline styles matching the issuer's font/size/color/alignment choices, showing the live preview text: `{amount} sats`, `For: {recipient_name}`, `{message}`.
- **Pointer events:** `@pointerdown`, `@pointermove`, `@pointerup` with `setPointerCapture()` for drag and resize. No external drag library (RESEARCH.md §3 — native pointer events, matches LNBits frontend stack).
- **Drag clamping:** QR and text positions clamped to preview bounds (`Math.max(0, Math.min(newX, previewWidth - elementWidth))`).
- **QR resize constraint (D-07):** `minQrSize = 150` (preview-scaled equivalent). Resize handler enforces `Math.max(minQrSize, newSize)`. User can drag larger but never smaller. Default size = minimum. The 150px minimum is enforced both client-side (resize handler) and server-side (render function validates — RESEARCH.md Risk 6).
- **No server round-trips during drag (D-06):** The preview is entirely client-side. QR placeholder is a static image or client-generated. Real QR is generated server-side only on submit/render.

**Text styling controls (D-08):**

| Control | Quasar component | Options | Default |
|---------|-----------------|---------|---------|
| Font family | `q-select` filled dense | DejaVu Sans, DejaVu Serif, DejaVu Sans Mono | DejaVu Sans |
| Font size | `q-slider` (min 12, max 72, step 1) | 12–72px | 24 |
| Font color | `q-input type="color"` (native picker) | any hex | `#000000` |
| Text alignment | `q-btn-toggle` (options: left/center/right) | left, center, right | left |

**Coordinate model (D-09 — RESEARCH.md recommendation):** Normalized fractions (0.0–1.0) for QR and text positions, stored as JSON. QR size stored as absolute pixels (scannability depends on absolute size). On submit, convert preview pixels to fractions:
```javascript
designConfig = {
  template_asset_id: this.templateAssetId,  // null for bundled
  template_name: this.selectedTemplate,      // 'portrait' | 'landscape' | 'custom'
  qr_x_frac: this.qrX / this.previewWidth,
  qr_y_frac: this.qrY / this.previewHeight,
  qr_size: this.qrSize,                      // absolute pixels (scaled to real template at render)
  text_x_frac: this.textX / this.previewWidth,
  text_y_frac: this.textY / this.previewHeight,
  font_family: this.selectedFont,
  font_size: this.fontSize,
  font_color: this.fontColor,
  text_align: this.textAlign,
}
```

**Submit behavior:** The existing `createGiftCard()` method sends the design config alongside the existing fields. The design config is serialized into `qr_config` and `text_config` JSON columns (RESEARCH.md §7). If the issuer skips the design section (no template selected), defaults apply: portrait template, QR at (0.1, 0.7) frac, size 200px, DejaVu Sans 24px black left-aligned text at (0.1, 0.1) frac.

**Post-creation result state:** Unchanged from Phase 1 — success message, redemption link, "Save this link" warning banner. No design preview in the result state (the design is visible on the redemption page).

### Screen 3: Email Delivery Dialog

**Trigger:** "Send Email" or "Add Email" button in the card list expanded row.

**Component:** `q-dialog` with `position="top"`, `q-card.q-pa-lg.q-pt-xl.lnbits__dialog-card` (standard LNBits dialog pattern).

**Component structure:**
```
q-dialog v-model="emailDialog.show" position="top"
└── q-card.q-pa-lg.q-pt-xl.lnbits__dialog-card
    └── q-form @submit="sendEmail"
        └── div.q-gutter-md
            ├── h6.text-subtitle1.q-my-none "Send Gift Card Email"
            ├── q-input "Recipient Email" type="email" (required, validated)
            ├── q-select "Email Mode" (Custom Text / Fancy HTML Template)
            ├── q-input "Subject" (default: "You have a gift card from {sender_name}")
            ├── div v-if="emailDialog.mode === 'custom'"
            │   └── q-input type="textarea" "Email Body" (issuer writes custom message)
            ├── div v-else
            │   └── q-select "HTML Template" (preset templates — D-19)
            ├── q-separator.q-my-md
            ├── div "Preview:"
            │   └── q-card.q-pa-md (email preview — subject + rendered body)
            │       ├── div.text-caption "Subject: {subject}"
            │       └── div.text-body2 (rendered HTML or text body)
            └── div.row.q-mt-lg
                ├── q-btn[unelevated,color="primary",type="submit"] "Send Email"
                │   :loading="emailDialog.loading"
                └── q-btn[flat,color="grey",v-close-popup] "Cancel"
```

**Email mode picker (D-18):**
- `q-select` with two options: "Custom Text" and "Fancy HTML Template".
- **Custom Text mode:** Shows `q-input type="textarea"` for the issuer to write their own body text. Minimal HTML wrapper applied server-side (`<p>{escaped body}</p>` with newlines → `<br />`).
- **Fancy HTML mode:** Shows `q-select` with preset Jinja2 template options (D-19 — 2-3 presets in `static/email_templates/`). The issuer does not edit the HTML — they pick a preset. The sender's message is injected into the template.

**Subject line (D-20):**
- `q-input` with default value "You have a gift card from {sender_name}" (pre-filled from card data).
- Issuer can override. Hint: "Defaults to 'You have a gift card from {sender}'."

**Email preview (D-21):**
- A `q-card.q-pa-md` section below the form fields showing a live preview.
- Shows the subject line and a rendered preview of the body (text for custom mode, simplified HTML render for fancy mode).
- Preview updates reactively as the issuer edits subject/body/mode.
- Label: "Preview:" in `text-caption`.

**Submit behavior:**
- Validates email format (Quasar `q-input` rule: `val => is_valid_email || 'Enter a valid email address'`).
- Calls `POST /giftcards/api/v1/cards/{card_id}/deliver` with `{recipient_email, email_mode, subject, body, template}`.
- On success: close dialog, `notify('Email sent successfully', 'positive')`, refresh card list (delivery status updates to `sent`).
- On failure: `notifyApiError(error)`, keep dialog open. Card's `email_status` set to `failed` server-side (D-23). Issuer can retry.

**SMTP not configured (D-22):**
- If the server returns an error indicating SMTP is not configured, show: `q-banner` with `color="warning"` icon `warning`: "Email delivery is not configured on this LNBits server. Contact your administrator to enable email notifications, or use Copy Link / Download PNG instead."
- The "Send Email" button remains disabled until SMTP is configured. Check on dialog open via a status endpoint or catch the error on first attempt.

## Interaction Contracts

### Card designer — drag interaction

| Interaction | Trigger | Behavior |
|-------------|---------|----------|
| Drag QR | `pointerdown` on `.draggable-qr` | Move QR element; clamp to preview bounds; update `qrX`/`qrY` reactive state |
| Drag text | `pointerdown` on `.draggable-text` | Move text element; clamp to preview bounds; update `textX`/`textY` reactive state |
| Resize QR | `pointerdown` on `.resize-handle` (`.stop` propagation) | Resize QR element; enforce `minQrSize=150`; clamp so QR stays within preview; update `qrSize` |
| End drag/resize | `pointerup` | Clear drag/resize state; release pointer capture |

**Pointer capture:** Use `event.target.setPointerCapture(event.pointerId)` on pointerdown to maintain drag tracking even if the cursor leaves the element. Release on pointerup.

**No server round-trips (D-06):** All drag/resize updates are purely client-side reactive state changes. The preview re-renders via Vue reactivity (bound `:style` on positioned elements). No API calls during drag.

### Card designer — template selection

| Interaction | Trigger | Behavior |
|-------------|---------|----------|
| Select bundled template | `q-select` change | Update `selectedTemplate`; load bundled template image as preview background; reset QR/text positions to defaults |
| Upload custom template | "Upload Custom Template" button click | Open file picker; on file selected → upload via `POST /api/v1/assets?public_asset=true` → store `asset_id` → load as preview background |
| Upload in progress | During upload | Show `q-spinner` in upload button; disable button |
| Upload failed | Error response | `notifyApiError`; keep previous template selection |

### Email delivery — validation

| Field | Rule | Error message |
|-------|------|---------------|
| Recipient Email | Required, valid email format | "Enter a valid email address." |
| Subject | Required (has default) | — (always pre-filled) |
| Email Body (custom mode) | Required if mode is custom | "Enter your email message." |
| HTML Template (fancy mode) | Required if mode is fancy | — (pre-selected default) |

Validation fires on form submit only (not on blur). Use `q-form @submit` with `lazy-rules` on `q-input`.

### Email delivery — send behavior

1. Issuer clicks "Send Email" → form validates.
2. `POST /giftcards/api/v1/cards/{card_id}/deliver` with email config.
3. Server sends email as a background task (`create_task` — RESEARCH.md §4). Endpoint returns immediately.
4. On success response: close dialog, `notify('Email sent successfully', 'positive')`, refresh card list. Delivery status badge updates to `sent`.
5. On error response: `notifyApiError`, keep dialog open. Delivery status badge updates to `failed`. Issuer can retry by clicking "Send Email" again.

### Claim page — email submission

1. Recipient enters email, clicks "Send Verification Link".
2. `POST /giftcards/api/v1/claim {email}`.
3. **Always** transition to "Check Your Email" confirmation state (D-14 — same response whether email has pending cards or not).
4. If email has pending cards: server generates magic link, sends notification email (no raw_token, no card image — D-12).
5. If rate limited (429): transition to "Too Many Requests" state.
6. On network error: `notifyApiError`, stay on email entry state.

### Claim page — magic link verification

1. On mount (if `:magic_token` in route): show loading state.
2. `GET /giftcards/api/v1/claim/{magic_token}`.
3. If valid + has cards: show pending cards list (State B).
4. If valid + no cards: show "No Pending Gift Cards" (State C).
5. If invalid/expired (404/410): show "Link Invalid or Expired" (State D).
6. Recipient clicks "Redeem" on a card → navigate to `/giftcards/redeem/{raw_token}`.

### Printable PNG download

1. Issuer clicks "Download PNG" in expanded row.
2. Browser navigates to `/giftcards/api/v1/cards/{card_id}/print` (or triggers via hidden `<a download>`).
3. Server renders branded card at scale=3 (RESEARCH.md §6), returns PNG with `Content-Disposition: attachment; filename="giftcard_{card_id}.png"`.
4. Browser downloads the file. No dialog needed.
5. On error: `notifyApiError`.

### Copy link (unchanged from Phase 1)

On click: copy redemption URL to clipboard, `notify('Link copied to clipboard', 'positive')`. Duration: 2000ms.

## Accessibility Notes

- All `q-btn` elements that are icon-only must include `aria-label` (e.g., `aria-label="Copy redemption link"`, `aria-label="Download gift card image"`).
- Branded card image must include `alt="Branded gift card with QR code"`.
- QR placeholder in designer must include `alt="QR code preview — drag to position"`.
- Template thumbnail images must include `alt="Portrait template preview"` / `alt="Landscape template preview"`.
- Error and status states use both color AND icon (not color alone) to satisfy WCAG 1.4.1 (Use of Color). Delivery status badges include icons (`mail_outline`, `check`, `error_outline`).
- Card designer drag handles must be keyboard-accessible: provide `tabindex="0"` and arrow-key handlers as a fallback for users who cannot use pointer events. (Planner's discretion on exact implementation — native pointer events are primary, keyboard is progressive enhancement.)
- Claim page: no LNBits header/drawer chrome — page is self-contained. Tab order: email input → submit button.
- Font color picker (`q-input type="color"`) must have a visible label and be operable via keyboard.
- Email preview must be readable — use sufficient contrast between preview text and preview card background.
